# 活俠傳 Mod 規格

這份文件記錄 repo 裡各個 Mod 目前的功能、規則與維護方式。改了規則或加了功能時一併更新這裡。

- 遊戲：活俠傳（Legend of Mortal），Unity 2020.3 Mono，**64 位元**（2026-10-15 更新後）
- 載入器：BepInEx 6.0.0-be.692 win-x64（遊戲目錄的 `winhttp.dll`）
- 原始碼：`C:\Users\zsein\Documents\LOM_Mods`（GitHub：zseineo/LOM_Mods，公開；測試版發在 Releases，每個 Mod 一個 tag：`<Mod>-v<版本>`）

| Mod | 資料夾 | 版本 | 用途 |
|---|---|---|---|
| LOM TimeMachine | `TimeMachine/` | 0.8.0 | 時光機存檔（F6）＋「算命仙」網頁（F7）＋事件紀錄＋作弊 |
| LOM CombatSpeed | `CombatSpeed/` | 0.1.0 | 戰鬥加速倍率（設定 `General.SpeedMultiplier`，預設 x6） |

## 1. TimeMachine：時光機存檔（F6）

### 設定（`BepInEx/config/zseineo.mortal.timemachine.cfg`）

### 存檔位置與檔名

- 根目錄：`%LocalLow%\Obb Studio\Mortal\TimeMachine\<SteamID>\`
  放在遊戲存檔資料夾外面：不占存檔欄位，也不會被 Steam 雲端同步。
- 每旬一檔：`<模式>\Y{年}_M{月:00}_S{旬}.dat`（AutoGameSave 格式；模式＝main／act1…）
- 關鍵節點：`<模式>\N_<節點id>.dat`
- 路線：預設路線＝根目錄本身；其他路線在 `_routes\<名稱>\`，目前路線記在 `route.txt`

### 覆蓋規則（使用者決定）

- 同一旬的新存檔覆蓋舊檔，但**還沒到達的未來旬不覆蓋**。
- 只寫入「目前路線」，不同路線互不覆蓋。「什麼算不同劇情線」尚未定案，要和使用者一起研究。

### 路線

- 「從目前時間分岔」：複製到現在為止的存檔成新路線；「空白」：新路線不含存檔。
- 路線旁「×」刪除；預設路線不可刪。

## 2. TimeMachine：「算命仙」網頁（F7）

網頁名稱是「算命仙」（使用者決定：提醒內容可能不準）；未讀分頁仍叫「五塊錢」（玩家梗：少玩劇情＝少玩五塊錢）。
傳奇（劇情摘要）與結局文本不放進網頁（測試版起）：`render_preview.py` 輸出時拿掉 `legend`、結局文字，graph.json 仍保留給分析用。

Mod 內建本機網頁服務，頁面檔在 `BepInEx/plugins/LOM_TimeMachine/guide/index.html`（由 `tools/rebuild_guide.sh` 產生）。
重建後網頁按 **F5** 就會更新，不用重開遊戲或 F7。改 Mod（.cs）才要重編、重開遊戲。

### API（GuideServer.cs）

遊戲資料一律在主執行緒（`Tick()`）讀取，HTTP 執行緒只回傳快照。中文參數自己從 `Url.Query` 解碼。
只聽 127.0.0.1（不寫 localhost：Mono 解析失敗會改聽所有介面）。Host 不是 `127.0.0.1:<port>` 的請求、Origin 不是本網頁的 POST 一律 403（擋其他網站偷送讀檔／作弊請求、DNS rebinding）。

| 路徑 | 說明 |
|---|---|
| `/` | 網頁本身 |
| `/api/state` | 遊戲時間、旗標、屬性、好感、圖鑑、最近執行的腳本（recent） |
| `/api/timemachine` | 時光機存檔清單 |
| `/api/load`（POST）、`/api/lastload` | 讀取時光機存檔 |
| `/api/positions` | 地點事件目前權重・機率（呼叫遊戲 PositionEventData.GetRate）＋強制清單 |
| `/api/force`（POST） | 地點事件強制觸發開關（ForcedDraws） |
| `/api/readkeys?from=N` | 遊戲已讀台詞鍵（增量） |
| `/api/icons`、`/api/icon?name=` | 角色頭像（從遊戲 sprite 轉 PNG，不存檔） |
| `/api/cheats`、`/api/cheat`（POST） | 作弊開關 |
| `/api/rels`、`/api/rel`（POST） | 好感一覽、改好感／設成已結識 |

| 分頁 | 內容 |
|---|---|
| 五塊錢 | 有台詞但沒讀完的段落＋怎麼看到（規則見第 5 節） |

上方開關：「防雷」（未讀內容模糊）、「列入差分」、「顯示腳本推算時間」；篩選器狀態記在瀏覽器 localStorage。

汗青書、死法（生死簿）分頁已拿掉，改看 smilin.net wiki。

### 寫法規則（使用者要求）

- 參考 smilin.net wiki 的短寫法：`處世<60`、`小師妹好感≥60`、`🚩「收留小梅」`（旗標用開發備註）、`選「X」（🎲≥50）`、`接續「X」`、`第2年3月下旬起`、`持有「X」`、`心上人是虞小梅`。
- 手寫的條件（`build_graph.py` 的 `TARGETS`、`tools/guides.json`）也照這些寫法；旗標代號、腳本名只放滑鼠提示（guides 的 `flags`）。
- 不寫「需要」等贅字；條件前面的 ✓／✗ 是**目前存檔**是否符合，不是「要／不要」。
- 旗標編號收成 ⓘ 小圖示（點開看設定位置）；內文不出現腳本名、旗標編號。
- 旗標浮動視窗每列寫「在哪個事件／地點行動」＋該段裡要選的選項或條件；怎麼進到那段太長，點開看。
- 暫存旗標（TC／A／B／C、Talk_Option…）翻成戰前／先前的選項或條件；查不到就寫「依戰前情況」或「要從特定的前段劇情進來」。
- 遊戲資料裡條件不存在的選項（`XXX`、`Meeting_Option_703_02_XXX`）遊戲判定不成立，不列。
- 前後要求互相矛盾、半路又沒有改旗標的路線，走不通，不列。
- 🏆：劇情有要成就（風雲史）才出現的分歧。分兩種：成就分支包住整段台詞 ≥ 80%＝「整段要成就」；否則＝「成就追加台詞」（不用成就也看得到這段）。事件細節同樣分開寫。
- 多值旗標＝有 0/1 以外的值、兩處以上累加、或只累加沒有直接設成 1；只在一處 +1 當開關用的（主角不在唐門）當成有／沒有。
- 有多種數值的旗標（進度、次數）寫出數值：`🚩「神兵帖進度」=1`；連上遊戲時後面加「（目前 N）」。開發備註尾巴的「(0/1)」不顯示。
- 「剛好是預定的時間」改寫成記下時間的事件或地點事件：`剛好是「鐵拳巷・打鐵．鍛造・被小竹無視」的1旬後`。
- 同名的事件有 3 個以上（每月的唐門會議）：路線裡不寫第一次的時間，免得看成只有那一次。
- 選項的「（需 …）」不寫「還沒選過／已選過」（選單本身的狀態）。
- 不給「這輪已錯過」之類的判定，讓玩家自己判斷（使用者決定）。
- 開發備註列了各數值意思（`1: 青城` 或 `1.飛天門`）就寫名稱：`留學：青城（目前：崆峒）`；`=0／≠0／≥1` 這類有沒有的條件寫「有／沒有」。
- 結緣旗標（攻略X，G1100x）：0 沒結緣、1 已結緣、2 結緣後決裂（修羅場打輸、滄幫對策罵上官螢時設）。上官螢的 1、小菊與瑞杏的任何值在劇本裡都沒有設定的地方。
- 次數旗標只有一個地方在累加時寫出在哪加；`（選A；選B）的累計次數=0` 寫成「A、B 都還沒選過」，`≥1` 寫成「選過其中之一」。
- 路線整理：前面選過「X」，後面的「先前選「X」」不寫；相鄰、比同一數值的條件合成範圍（`嘴力 30～34`），中間隔著選項的不合；文字一樣的路線只列一次。
- `秘笈等級·X=5` 寫成「「X」練到 5 級」；「X死亡」的反面寫「X還活著」；遊戲內旗標名稱重複時改用開發備註。
- 「怎麼看到」裡寫出來一樣的條件合成一行、句數相加；合併卡裡條件一樣的小節寫「其一／其二」。
- **做不到的旗標不列**（使用者確認，`build_graph.py` 的 `NEVER_FLAGS`、網頁同名常數要一致）：攻略上官螢／攻略小菊／攻略瑞杏（未實裝結緣）、試玩版（Demo）、序章旗標（Prologue）一律當成 0。
  要它們成立的路線、事件（含只接在這些事件後面的接續段落）、未讀段落、「怎麼看到」的原因、地點事件結果都不列；條件裡一定不成立的「或」選項、一定成立的部分也不寫。
  小菊在唐門不算：西武林盟期間特定路線（崆峒回音）小菊會在唐門。
- **可能無法達成**（只標註、不隱藏）：旗標要的值，Lua 劇本的 SetFlag 都設不出來（預設 0）。有 AddFlag、暫存旗標、決鬥／戰役會改的、小遊戲與商店（Pinball_、Shop_、Score_）不算，因為遊戲程式可能會改。
  條件後面標「⚠可能無法達成」，觸發條件這樣的事件標在標題旁和事件說明裡。資料是 graph.json 的 `maybeValues`。
  暫存旗標查不到設定位置（寫成「要從特定的前段劇情進來」）的也標。
- 單一設施旗標寫地產名稱：`還沒贖回「藥鋪」`（多個加總才是「已建設施數」）；`隨機(0~30)≤10` 寫成「機率約 35%」；每月都有的事件（唐門會議）在條件來源裡不寫第一次的時間。
- 合併逐步列時，某一步的選法剛好是「X」和「以上皆非（不是：X）」：怎樣都會過，那一步不寫。
- 暫存旗標的條件在 0 也成立時（A≠1、A<2）：寫成「先前沒有選設成不符合值的那個」或「「X」都還沒選過」，不寫成「先前選了設成其他值的」；設的值全都符合就是「這段劇情裡一定成立」。查不到時再找同一章（chX_Y）其他事件設的地方；不是 chX_Y 的劇本，名稱去掉最後的編號一層層找同系列（act2_1 → act2_2、travel_result_601_101 → _101_01）。
- graph.json 的旗標設定位置全部輸出（以前每個旗標只留 12 處，暫存旗標、丐幫好感度這類共用很多處的會漏）。
- 全部是「且」的條件，寫出來一樣的項目只留一個（括號跨項目的不合）。
- 次數類旗標（名稱結尾是次數、數量、天數、值、進度）的 =0、≥1 也寫數值；門派好感度不掛 🚩；備註列了數值意思的旗標 =0 寫「X：無」；備註數值用空白分隔（「1 不跟隨大師兄」）也認。
- 範圍：同一個條件裡「A≥20 且 A<60」寫成「A 20～59」；「不是（A<0；A>0）」取交集；交集剛好是原本某個條件就照原本的寫。
- 「已開發·開發項目_X」寫成「已開發／還沒開發「X」」，「開發等級·…」寫成「「X」開發等級≥N」；秘笈 0 級寫「沒練／練過「X」」；兩個天賦加總寫「有天賦「A」或「B」」；「條件·X ≠ 1」寫成「不是「X」」。
- 累計次數的來源有多個時用括號：「（選A；選B）的累計次數」；勝利、落敗都會加的寫成「戰鬥的累計次數」。
- 檢查工具：scratchpad 的 `mk_audit.py`＋`audit_check.py`＋`audit_tmpl.py` 把網頁會用到的每個條件輸出成「原始 → 寫法」，自動找漏出的代號、重複字、正反可疑，再依樣式分組人工讀。
- 限定路線標籤（頑抗、西武林盟、留學：崆峒…）會往上繼承。

### 流程圖分段

- 段落依劇本章節：入門（1年4～9月）、南宮壽宴（1年10月～2年1月）、不留學／崆峒留學／青城留學（都是 2年2～11月）、唐門內戰・臥雲崗（2年12月～3年2月）、
  小師妹招親（3年3～5月）、雪山・武林大會（3年6～10月）、決策（3年11月～4年2月）、終局（4年3月～）；另有「時間不定」（沒有固定時間、每月固定時間）。
- 三條留學線依限定路線或地點判斷（崆峒、江陵→崆峒；青城→青城；唐門 8 月上旬前→不留學和青城，之後→不留學；判斷不出來的三條都放）。
- 每旬一列，事件依地點分欄；期間型事件放在最早可能發生的那一旬，卡片寫出期間。
- 角色篩選（同五塊錢的角色）：事件裡有她說話、立繪、傳說或旁白提到。大圖模式是把其他事件淡化。
- 從其他分頁點事件，會切到那個事件所在的段落並捲過去。
- 段落與篩選記在瀏覽器；連上遊戲時目前那一旬會標色。
- 五塊錢不顯示地點（地點是從背景圖推的，常不準）；流程圖仍用地點分欄。

### 事件切段

長劇情依劇本段落編號 `chX_Y` 換段斷開，後面另成「接續」事件（`Part/<段落>`）；留學自由行動選單（`section_0N_free_start`）自成一段。
段名先看 `PART_NAMES`（手動），再用該段決鬥說明開頭（「崆峒神威 刺客」→崆峒神威）。新段落沒名稱時要補進 `PART_NAMES`。

### 事件名稱

優先用 smilin.net wiki「主支線簡易表格」的事件名（`tools/match_wiki.py` 依選項文字＋時間自動配對，結果在 `tools/wiki_names.json`；
配錯的直接改那個檔、加 `"manual": true`，重跑時會保留）。事件細節會附 wiki 連結和遊戲內名稱。沒對上的照舊用開發者備註或第一句台詞（和傳奇同一段文字的旁白不用）。

### 事件備註

遊戲資料本身的問題或不直觀的規則，寫在 `build_graph.py` 的 `EVENT_NOTES`（例如「好多錢」兩個時間條件衝突、觸發不了）。

## 3. 事件紀錄（除錯用）

使用者回報「事件觸發不出來」時，先看這兩個檔再下結論：

## 5. 五塊錢的未讀判斷

### 已讀來源

遊戲自己的已讀紀錄（ReadStorySystem，記的是每句台詞的鍵）。
**發布版（預設）**：重建時不讀存檔，所有有台詞的段落都進五塊錢；連上遊戲時每 3 秒從 `/api/readkeys` 取已讀，網頁即時重算已讀比例、角色句數、「怎麼看到」。
每段帶分支樹 `rt`（每層台詞 k、分歧 sub、分支 br：l 標籤／d 顯示名稱／x 不當原因／n 做不到／v 差分），網頁的 `liveReasons` 和 build_graph 的 `unread_reasons` 同一套規則；台詞樹 `kt` 也由 `rt` 推出。
沒連上遊戲時全部當未讀。`rebuild_guide.sh --save` 用自己的 `Save_universe.json` 建（比對用：連上遊戲時兩版五塊錢應完全一樣）。

### 單位與計算

- 以**一支劇本（段落）**為單位，算「讀過的台詞數 ÷ 台詞總數」（重複的台詞只算一次）。
- 只算台詞和旁白；**選項文字不算**（遊戲從來不記選項的已讀）。
- 遊戲裡不會出現的選項（條件不存在）底下的台詞不算。
- 比例 < 1 的段落才列出：
  - 0%：整段未讀，列出「怎麼進來」（觸發時間、條件、路線）。
  - 事件已經開始、這段卻 0% 的：標「◇ 分支」（玩過的事件裡沒走到的分支）。
  - 0～100%：部分已讀，列出「怎麼看到」：沒讀的台詞在哪個分支、要怎麼走（最多 12 項）。這是從劇本推的，不是存檔記下的原因。

### 劇情分支與差分

| 種類 | 定義 | 未讀怎麼算 |
|---|---|---|
| 劇情分支 | 選項、擲骰、戰鬥勝負、旗標條件造成的分歧；或屬性條件但劇情走向不同 | 每個分支的台詞都要讀過 |
| 差分 | **只看屬性**（性情、道德、處世、修養、學問、嘴力、心相、陰陽、內力、體力、廚藝、輕功、變心、武學／毒藥／鍛造點數、天賦）、和選項無關，而且**走向相同**（接下去的劇本、任務、場景、結局都一樣）的台詞分歧 | 預設：每組看過其中一種就算讀過；勾「列入差分」：每種版本都要讀過 |

差分常常也會改 NPC 的台詞（不只趙活），判斷看條件，不看說話的人。

### 怎麼進來、怎麼看到

- 讀了一部分的段落也列「怎麼進來」（最短的一條路線）；自由行動選單裡的段落依「留學期間・地點」分組。
- 事件還沒觸發：分組標題底下分欄寫「地點／觸發／接續」「前置」「備註」（時間已在標題）；地點沒指定的寫「在X，時間到自動觸發」。
- 合併卡：同時間、同前置、只差地點的地點事件（例：第2年8月中旬的唐門各處）合成一張，地點列成一排可以點；同名同時間的事件（偷懶怪的三個階段）合成一張，每個寫自己的條件。
- 試玩版限定：要「序章旗標」（Prologue）= 1 的事件只在試玩版（Demo = 1）出現，收在最後一張「試玩版序章才有的劇情」，不算進上方的段數。
- 長路線：多條路線結構相同、而且每一步最多帶一個條件，才合併成逐步列（同一步不同選法寫「或」）；其他的每條都 ≤ 4 項照原本寫；否則只列最短的一條「要做的事」（選項、擲骰、戰鬥、到哪個事件），條件 ≤ 2 個寫在「另外要」，再多就收成「另外要符合 N 個條件」，其他路線收起來。
- 讀了一部分的段落，「怎麼進來」只剩「看當下條件」時不寫。
- 重畫（連上遊戲更新已讀）時用「上層摺疊標題＞自己標題＃第幾個」保留展開狀態，不用位置序號（卡片增減會錯位）。
- 上方「目前」那一列的腳本代號可以點，跳到流程圖那一段（地點事件跳地點事件分頁）。
- 點段落標題會跳到流程圖：切到所屬事件、右側捲到那一段（#N）並閃一下，可以沿上層分支、「接到 #N」往回找入口。
- 流程圖右側反過來：事件的「NN% 已讀 ›」、段落的「NN% 已讀 ›」（和「過場對話」）點了跳回五塊錢那個事件／那一段；被狀態或角色篩選藏起來就先清掉篩選。流程圖只畫會改變結果的分歧，只換台詞的分歧要到五塊錢看。
- 右側「劇情」區：每個分支前標 ✓ 讀完／◐ 讀過一部分／○ 沒讀過，後面寫 N%・剩幾句（連上遊戲即時算：summarize 的分歧帶前序編號 `ri`，對到五塊錢分支樹 `rt` 的同一個分歧；分支本身沒台詞的看接下去的段落，最多往下 3 層）。
  只有過場的段落縮成一行；接回事件開頭寫「↩ 回到選單」（自由行動）／「↩ 回到開頭」；同一段接到同一處只寫一次。
  同一個旗標往下判斷 3 支以上（鐵拳巷看造訪次數）：抬頭寫「依 🚩X（目前 N）判斷，由上往下先符合的先走」，各支只寫值和「另需」。自由行動事件最上面說明這是每旬重複的選單。
- 五塊錢裡從留學自由行動進去的段落：依選單選的地點分組（「鶴崖（崆峒留學的養成地點）」，下面寫選單上出現的條件）；
  地點選項後面的判斷另成一步（「以上皆非」那支是一般情況不寫）；段落名稱＝地點・路上「旗標 X = 0」而那段把 X 設成非 0 的開發備註（「觸發 鶴崖事件 又一個被騙」→ 又一個被騙），沒有就用那一步的條件。
- 不屬於任務事件的段落（日常、地點行動）：路線前面補上起點連結——「在〔事件〕中」跳流程圖、「在地點事件〔地點・行動〕」跳地點事件分頁那一列、「點進〔地點〕時」跳地點卡；地點事件段落的標題也跳地點事件分頁。開場、閒聊選單、找不到起點的不加連結。

### 怎麼看到（原本叫「沒讀到的原因」）

由外往內找：0% 的分支直接列出（選項／擲骰／戰鬥／條件／隨機／差分），部分讀過的分支再往裡面找。
差分的原因只在勾「列入差分」時顯示。

### 角色篩選

- 選項：女主角（小師妹、葉雲裳、龍湘、虞小梅、夏侯蘭、郁竹、上官螢、魏菊…）＋瑞笙、南溪、孟仙謠；「其他」＝沒有這些人。
- 逐句判斷每句台詞算誰的：**她說的台詞**（setcharacter 指定的說話者），以及**旁白裡提到她名字的句子**。趙活的台詞不算任何人的。
- 整段未讀：她有出場（說話、立繪、傳說紀錄提到）或有她的句子，就列。
- 選了角色時，上方的總句數只算她的句子（她說的＋旁白提到她的）；每段的百分比仍是整段。
- 讀了一部分：要有她的句子還沒讀才列；原因清單只顯示含她句子的那幾項（都沒有就全列）。
- 連上遊戲時用即時已讀判斷；條件裡出現名字（例如「虞小梅好感<30」）不算。
- 旁白用「她」「少女」代稱、沒寫名字的句子判斷不到。
- 地點事件分頁的篩選是「事件跟她有沒有關」：說話、立繪、傳說或台詞／旁白提到、地點名稱寫明是誰的（「小梅找你跑步」）都算。

### 流程圖、地點事件的已讀

用同一套算法（含「列入差分」開關）。

## 6. 資料與建置

```
遊戲更新 → bash tools/refresh_data.sh   # 重抽 Lua、在地化、設定物件、戰鬥、反編譯到 data/（舊的改名 data_old_<時間>；data/wiki_events 快取會沿用）
更新後    → python -I tools/diff_graph.py data_old_<時間>/graph.json data/graph.json  # 事件條件、劇本分歧、手寫條件用到的旗標有變的，逐項對照 TARGETS／guides.json 改寫
改規則    → bash tools/rebuild_guide.sh  # 發布版；build_graph.py → data/graph.json → render_preview.py → 安裝到遊戲（--save 用自己的已讀）
改 Mod    → cd TimeMachine && dotnet build -c Release，複製 bin/Release/LOM_TimeMachine.dll 到 BepInEx/plugins/LOM_TimeMachine/
```

- `data/`、`preview/` 不進 git（遊戲文字、可重建）。
- 遊戲資產字串是 Big5 誤存，UnityPy 讀出會亂碼：一律用在地化文字或 ASCII 名稱。
- 存檔旗標：`tools/SaveDump`（`SaveDump.exe <存檔> [旗標前綴...]`）。

### build_graph.py 常改的表

| 名稱 | 用途 |
|---|---|
| `TARGETS` | 其他條件分頁的目標（brief 格式：conds／steps，每項 `{t, c}`，c 是存檔檢查式如 `flag:G10004=1&rel:girl5>=20`；可加 `pop: {text, flag, op, val}` 把 text 那幾個字做成可點的旗標，列出設定／累加位置） |
| `HEROINES` | 女主角與結緣旗標、結緣結局 |
| `PART_NAMES` | 切段段名 |
| `EVENT_NOTES` | 事件備註 |
| `PLACE_OVERRIDES`、`VIEW_PLACE`、`WORD_PLACE` | 事件地點判定 |
| `POSITION_GROUPS` | 地點事件的地點、動作名稱、抽籤組 |
| `ROUTE_FLAG_NAMES`、`ROUTE_PREFIX` | 限定路線標籤 |

手寫攻略：`tools/guides.json`（romance：各女主角結緣步驟；文字裡 `||…||` 是防雷）。

### 測試

- JS 語法：抽出頁面最後一個 `<script>` 用 `node --check`。
- 畫面：mock server（模擬 `/api/*`）＋無頭 Chrome 截圖／dump-dom；稽核腳本會開所有分頁、點所有事件，掃原始旗標、含糊說法、XXX 等。
- 改 Python 的修補腳本要注意換行：`build_graph.py` 是 CRLF，`flowchart_template.html` 是 LF。

### Git

每完成一項就 commit 並 push（commit 結尾加 `Co-Authored-By`）；大改前先 commit，rewind 後用 git 核對狀態。

## 名詞

| 名詞 | 意思 |
|---|---|
| 旬 | 上旬／中旬／下旬，遊戲最小時間單位；每旬有行動次數 |
| 劇本／段落 | 一支 Lua 劇情腳本（例如 `ch5_6_1`） |
| 事件 | 任務檢查點（MissionCheckData）觸發的一串劇本；長的再切成接續段落 |
| 地點事件 | 養成地點行動時依權重抽出的結果（PositionResultData） |
| 暫存旗標 | TC／A／B／C 開頭、Talk_Option 等，每段劇情重設 |
| 任務時間 | 劇本用 SetMissionTime 記下「現在＋多久」，條件「目前時間 = 任務時間」就是到了那時 |
| 差分 | 見第 5 節 |
